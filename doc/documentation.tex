\section{Double Outlets}
% ----------------------------------------------------------------

\subsection{Calculation Methodology}

Double RJ-45 Cat\,6 outlets are installed in every networked room.
The minimum density follows the standard of \textbf{one double outlet
per 10\,m\textsuperscript{2}} of usable floor area, rounded up,
with a minimum of one double outlet per planned workstation position.

Each double outlet provides \textbf{two simple (single) RJ-45 sockets}.

\begin{equation}
  N_{\text{double}} = \left\lceil \frac{A_{\text{room}}}{10} \right\rceil,
  \qquad
  N_{\text{simple}} = 2 \times N_{\text{double}}
  \label{eq:outlets}
\end{equation}

\subsection{Explicit Calculation Example -- Room 1.1 (Type A)}

\begin{itemize}[noitemsep]
  \item \textbf{Room:} 1.1, Type A, Standard Office
  \item \textbf{Dimensions:} $6.5\,\mathrm{m} \times 8.5\,\mathrm{m}$
  \item \textbf{Floor area:} $A = 6.5 \times 8.5 = 55.25\,\mathrm{m}^2$
  \item \textbf{Distribution frame:} MDF
\end{itemize}

Applying Equation~\ref{eq:outlets}:
\begin{align*}
  N_{\text{double}} &= \left\lceil \frac{55.25}{10} \right\rceil
                     = \lceil 5.525 \rceil = \mathbf{6\;\text{double outlets}} \\[4pt]
  N_{\text{simple}} &= 2 \times 6 = \mathbf{12\;\text{simple outlets}}
\end{align*}

\section{UTP Cable Quantity Calculation}
% ----------------------------------------------------------------

\subsection{Calculation Methodology}

For each room, the total UTP cable needed equals the number of simple outlets
multiplied by the cable length per outlet.
The cable length per outlet accounts for:
\begin{itemize}[noitemsep]
  \item the \textbf{horizontal distance} from the distribution frame to the room ($d_{\text{DF}}$);
  \item the \textbf{average cable span inside the room} to reach each outlet ($l_{\text{avg}}$);
  \item a \textbf{technical reserve} of 6\,m per cable (3\,m at the outlet side + 3\,m at the patch-panel side).
\end{itemize}

\begin{equation}
  L_{\text{room}} = N_{\text{simple}} \times \bigl(d_{\text{DF}} + l_{\text{avg}} + 6\bigr)
  \label{eq:utp_cable}
\end{equation}

\subsection{Detailed Example -- Room 1.1}

\begin{itemize}[noitemsep]
  \item Simple outlets: $N_{\text{simple}} = 12$
  \item Distance from room to MDF: $d_{\text{DF}} = 9.4\,\mathrm{m}$
  \item Average cable run inside room: $l_{\text{avg}} = 14\,\mathrm{m}$
  \item Technical reserve: $r = 6\,\mathrm{m}$
\end{itemize}

\[
  L_{\text{room 1.1}} = 12 \times (9.4 + 14 + 6) = 12 \times 29.4 = \mathbf{352.8\,\mathrm{m}}
\]

\section{Fiber Optic Cable Calculation}
% ----------------------------------------------------------------

\subsection{Backbone Topology}

The four distribution frames are interconnected by OM4 multimode
fiber optic (50/125\,\textmu m) in a \textbf{redundant ring/mesh topology},
providing multiple paths between any two DFs.
The node labelling used in the cable-planning spreadsheet is:

\chapter{Packet Tracer Simulation}

This chapter documents the Packet Tracer simulation built to validate the
logical design described in the previous chapters.
Because Packet Tracer does not support the modular Cisco Catalyst 9410R
chassis or the Palo Alto PA-3440 firewall, equivalent Packet Tracer
device models are substituted while preserving the same logical behaviour:
VLAN segmentation, inter-VLAN routing, VoIP telephony, wireless
connectivity, DHCP address assignment, Internet reachability, and
Management VLAN isolation are all demonstrated.

% ----------------------------------------------------------------
\section{Network Topology Overview}
% ----------------------------------------------------------------

The simulated topology follows a two-zone structure of
the physical design: one \textbf{MDF} cluster and one IDF cluster, interconnected by a shared backbone trunk.

\begin{figure}[H]
  \centering
  \includegraphics[width=\linewidth]{figures/pkt_simulation.png}
  \caption{Packet Tracer -- Simulated Network Topology.}
  \label{fig:pt_topology}
\end{figure}

Each IDF cluster is built using \textbf{data switches}
(Cisco 2960-24TT) for workstations, laptops, access points and IP phones.
The MDF core switch connects the IDF over a shared
backbone trunk (fa0/6--fa0/10).
The firewall sits between the ISP router and the MDF core switch,
enforcing the perimeter policy described in
Chapter~\ref{chap:environment}.

% ----------------------------------------------------------------
\section{IP Addressing and DHCP}
% ----------------------------------------------------------------

The simulation uses the \textbf{10.1.10.0/24} block for all
infrastructure and end-device addresses.
A dedicated \textbf{Server-PT} (10.1.10.2) acts as the centralised DHCP
server, distributing addresses to all end devices laptops, tablets,
smartphones, IP phones).
The default gateway for all pools points to the MDF core switch
(10.1.10.18).

All end devices confirmed a successful DHCP lease before any
connectivity test was performed.

% ----------------------------------------------------------------
\section{VLAN Configuration and Inter-VLAN Routing}
% ----------------------------------------------------------------

The MDF core switch (Cisco 3560) is configured with three VLANs covering
the three principal traffic classes present in the building:

\begin{table}[H]
  \centering

  \label{tab:pt_vlans}
  \begin{tabular}{C{1.5cm} L{3.5cm} C{3cm} L{3.5cm}}
    \toprule
    \textbf{VLAN ID} & \textbf{Name} & \textbf{Subnet} & \textbf{Purpose} \\
    \midrule
    1   & Data / Default & 10.1.10.0/24 & Workstations, laptops, management \\
    \rowcolor{rowgray}
    10  & Voice          & 10.1.10.0/24 & IP phones (voice VLAN on phone ports) \\
    20  & Wireless       & 10.1.10.0/24 & AP-associated wireless clients \\
    \bottomrule
  \end{tabular}
\end{table}

All inter-switch links operate as \textbf{802.1Q trunks}.
Phone-facing ports are configured in voice VLAN mode
(\texttt{switchport voice vlan 10}), allowing Cisco 7960 phones to
register with the CME router while passing data traffic on the native
VLAN.
Inter-VLAN routing is performed on the MDF 3560 SVIs. Connectivity
between data clients, voice clients, and wireless clients was verified
by \texttt{ping} tests across each pair before proceeding to
feature-specific testing.

% ----------------------------------------------------------------
\section{Wireless LAN}
% ----------------------------------------------------------------

Six access points (AP1--AP3 on the ground floor connected to the MDF
data switch; AP4--AP6 on the first floor connected to the IDF data
switch) are managed centrally by the \textbf{WLC-2504} Wireless LAN
Controller, which is connected to the MDF core switch.
The controller broadcasts the SSID \texttt{CND-Wireless} with WPA2-PSK
authentication (\texttt{CND12345}).

Wireless connectivity was verified on both floors:
\begin{itemize}[noitemsep]
  \item \textbf{Ground floor:} Laptop7, Tablet~PC0, Smartphone0, and
        Smartphone0(1) associated with AP1--AP3 and received DHCP addresses.
  \item \textbf{First floor:} Laptop8 and Smartphone1 associated with
        AP4--AP6 and received DHCP addresses.
  \item All wireless clients successfully pinged wired laptops on the
        opposite floor, confirming end-to-end routing through the MDF core.
\end{itemize}

% ----------------------------------------------------------------
\section{Internet Connectivity}
% ----------------------------------------------------------------

A Cisco 2911 \textbf{ISP router} is connected to the WAN interface of
the firewall.
A web server simulating \texttt{www.ciscobook.com} is attached to the ISP
router to represent an external Internet destination.
The firewall performs NAT, translating internal 10.1.10.0/24 addresses
to the public IP defined in Chapter~\ref{chap:vlans} (203.0.113.6).
Successful HTTP access from an internal laptop to the external web server
was demonstrated, confirming that NAT and the firewall perimeter policy
operate correctly.

% ----------------------------------------------------------------
\section{Management and SSH Access}
% ----------------------------------------------------------------

A dedicated \textbf{Admin PC} (PC2, credentials
\texttt{admin}/\texttt{Admin123}) represents the only authorised
management host.
All switches and the CME router are configured with SSH; RSA keys are
generated on each device and login is restricted to the
\texttt{admin}/\texttt{CND12345} local account.

Isolation was verified by confirming that a data-VLAN laptop was unable
to ping the MDF core switch management address (10.1.10.18), but the
Admin PC successfully opened SSH sessions to every switch and router in
the topology.
